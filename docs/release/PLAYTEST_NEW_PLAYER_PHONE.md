## 1. Как открыть сборку на телефоне (без dev-команд)

### 1.1 URL для игрока

1. Owner публикует **preview** (рекомендация: Firebase Hosting channel — см. [PREVIEW_HOSTING.md](./PREVIEW_HOSTING.md)) из согласованного коммита ветки **r6**.
2. Игрок получает **одну HTTPS-ссылку** без параметров, например:  
   `https://punk-me-40605--scenario-preview-XXXXXXXX.web.app/`  
   **Запрещено** добавлять в ссылку для human-теста: `?dev=1`, `?qa=1`, `?solo=1`, `?firebaseEmulator=1`, `?episodeCapture=1`, hash-отладку и т.п.
3. Открытие: обычный браузер телефона (**Safari** на iOS, **Chrome** на Android). Рекомендуется **приватная вкладка / InPrivate**, чтобы не подтянуть старый `localStorage` с `punkme_dev` / `punkme_qa`.
4. При первом заходе — **гостевой** сценарий (anonymous auth), без инструкций «включите эмулятор» и без ПК.

### 1.2 Что игрок **не** должен видеть и делать

- Нет консоли, нет bookmarklet, нет «вставьте в адресную строку…».
- Нет отдельного «QA-меню», читов на 9999 монет, кнопок «применить snapshot», `window.__punkApplyFirebaseSnapshot` и прочих хаков — это только для автотестов на localhost.
- Язык и героя игрок выбирает **в UI игры** (как обычный новичок), не через query-параметры.

### 1.3 Pre-flight для Owner (до выдачи ссылки игроку)

Проверка **на том же URL**, который получит игрок (можно с десктопа + один раз с телефона Owner):

| # | Проверка | Ожидание (pass) |
|---|----------|-----------------|
| P1 | Открыть URL **без** query | Загрузка → выбор персонажа → «Начать» → игра |
| P2 | Открыть `URL?dev=1` | На Firebase preview / prod client **нет** режима «бесконечные монеты»; `devCoinsEnabled` отключён на production client (`js/game.js`) |
| P3 | Открыть `URL?qa=1` | Нет QA-only UI; запись не ломается «тихим» блоком save из-за dev-флагов на prod |
| P4 | `localStorage` с `punkme_dev=1` / `punkme_qa=1` (симуляция) | На production client save с dev-флагами **блокируется** (`prodDevWriteBlocked`) — игрок не должен попадать в такое состояние при чистой приватной вкладке |
| P5 | `?firebaseEmulator=1` на **не-localhost** | Не использовать в human kit; на preview URL эмулятор не является «нормальным» входом для CEO phone test |
| P6 | Версия в UI (если есть `GAME_VERSION` / badge) | Совпадает с записью Owner (коммит / label r6) |

Если любой пункт P2–P5 ведёт себя иначе — **не** запускать human phone test до исправления сборки.

## 2. Протокол 10 минут (игрок + запись)

**Длительность:** ровно **10:00** от первого осмысленного действия игрока после «Начать» (см. лист наблюдений).  
**Правило:** наблюдатель **молчит** — не жесты, не «нажми сюда», не чтение подсказок вслух. Допустимо только: «время», «стоп» по окончании 10 минут.

### 2.1 Подготовка (до таймера)

1. Заряд телефона ≥ 50 %, режим «Не беспокоить», яркость фиксированная.
2. Включить **запись экрана** (системный звук — по возможности; микрофон игрока — опционально).
3. Игрок открывает **чистый URL** (§1), проходит выбор языка/героя и нажимает **«Начать»**.
4. Наблюдатель фиксирует **T0** = момент, когда игрок **первый раз** двигает персонажа или вращает камеру (не время загрузки).

### 2.2 Запись экрана

**iOS (Safari / любой app):**

1. *Настройки → Пункт управления* — добавить «Запись экрана».
2. Провести Control Center → удержать «Запись экрана» → включить микрофон при необходимости → «Начать трансляцию».
3. Перейти в браузер с игрой. По окончании — остановить запись; файл в «Фото».

**Android (Chrome):**

1. *Быстрые настройки → Запись экрана* (или Google Play Games / производитель).
2. Разрешить захват экрана + звук приложения, если доступно.
3. Открыть Chrome с URL игры. Остановить запись; сохранить файл (Gallery / Files).

**Артефакт:** видео + заполненный лист (§3) хранятся **вне git** (Drive, Notion, owner vault). В репозиторий кладётся только **анонимизированный** вывод (без PII), если Owner решает приложить к приёмке.

### 2.3 Что считается «глава 0» для этого теста

Цепочка `q_ch0_newbie` (см. [QUEST_TABLE.md](./QUEST_TABLE.md)): пробуждение → мама / кухня → щенок → журнал → зеркало → движение → взаимодействие → обход дома → выход на **улицу** → **разговор с Рейзором**.  
**Pass по задачам:** onboarding **завершён** (игрок на улице, знакомство с Рейзором состоялось) **внутри 10 минут** после T0.

### 2.4 Стоп-сессия

- По **10:00** наблюдатель говорит «стоп»; игрок прекращает (можно дойти до ближайшего безопасного места).
- Короткий **post-survey** (устно, 1–2 мин, **после** остановки записи или в конце видео): «О чём была история?», «Что было непонятно?», оценка 1–5 (§3).

## 4. Критерии pass / fail (human gate)

**PASS** (все пункты):

1. **Старт без посторонней помощи** — после выдачи ссылки игрок сам доходит до «Начать» и первого действия (Owner не объясняет управление заранее; допустима только фраза «это игра в браузере, 10 минут»).
2. **Сюжет** — на post-survey игрок **хотя бы частично** описывает завязку («проснулись дома», «мама / кухня», «нужно выйти / банда / Рейзор» — не обязательно имена, но направление верное).
3. **Задачи гл. 0** — onboarding **завершён** (улица + Рейзор) **до** окончания 10 минут от T0.
4. **Нет блокера** — нет hard-stop (белый экран, бесконечная загрузка, невозможность двигаться, soft-lock без выхода, crash вкладки).

**FAIL** если любой из:

- не может начать без подсказок наблюдателя;
- за 10 минут не завершил гл. 0;
- блокер воспроизводится на видео;
- игрок **не** понимает, зачем он в игре (post-survey «не знаю / просто ходил»).

**Не путать с AUTOMATED:** `npm run test:honest-ch01-emulator-e2e` — input-only, эмулятор, **не** заменяет этот human gate.
